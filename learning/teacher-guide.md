# 担当者向けガイド

## 対象と目的

想定8作品。主対象は高専1・2年生、Pythonを使う2人は3年生です。
問いは「プログラミング未経験者は、AIの助けでゲームを作り、その仕組みをどこまで理解できるか？」です。
制作できた事実と、学習後に説明・変更できた事実を別々に記録します。
参加者の経験やAIの使用状況を確かめ、未経験者以外の結果も区別します。

## 準備

1. 各作者にゲームのリポジトリURL、起動方法、依存パッケージ、公開用の名前を確認する。
2. 学習開始前のゲームを動かし、本人が元の状態をGitに保存する。
3. 学生向けガイド、ワークシート、4つのプロンプトを配布する。
4. 学習前の5問へ、本人がAIを見ずに回答する時間を設ける。
5. 制作履歴は残っている事実だけを集める。後から時間やプロンプトを創作しない。

## 50分×4回の進行例

| 回 | 進行例 | 担当者の確認 |
| --- | --- | --- |
| 1 | 10分：元の動作と事前回答、25分：AIで整理、15分：差分と動作確認 | 説明コメントを付ける作業と機能変更が混ざっていないか |
| 2 | 10分：資料生成、25分：重要な3箇所を読む、15分：言い換えと質問 | 資料のファイル名・関数名が現行コードと一致するか |
| 3 | 10分：独力の回答、25分：予測と変更実験、15分：結果の説明 | 本人が予測・編集・結果比較を行ったか |
| 4 | 20分：3ページ原稿と説明文、15分：本人による確認、15分：発表と質問 | 学習したという記述に本人の回答や実験の証拠があるか |

ゲームの規模や経験によって調整してください。全員にコード全体の説明は求めず、主要な処理を1つ追うことから始めます。
3年生には、実際に使うクラス・状態・イベント等の説明を1つ追加します。Pythonの有無だけで一律に高度な課題を課さないでください。

## 観察の基準

各項目を0〜2で記録します。0＝未確認または説明できない、1＝ヒントを使えば説明・実行できる、2＝独力で説明・実行できる。
AIが付けた点数をそのまま採用せず、本人の回答と短い口頭確認から担当者が判断します。

| 観察項目 | 確認する行動 |
| --- | --- |
| ファイルの役割 | 画面、見た目、処理を実際のファイルに対応させる |
| 入力から結果まで | 選んだ操作が、判定・表示に伝わる順をコードで追う |
| 値と条件 | 変数の意味・単位、得点や終了条件を説明する |
| 変更実験 | 予測を先に書き、1箇所変更し、結果と比較して戻す |
| AIの助けの説明 | AIに頼んだことと本人の判断・確認を記録から区別する |

開始前と学習後に同じ基本5問を使い、0〜2の内訳と回答を残します。
点数は今回の活動の観察用です。一般的なプログラミング能力の測定値として扱わないでください。
判断が曖昧な場合は「未確認」を残し、合計点だけで理解済みと決めないでください。

## 紹介ページと発表の確認

作者の提出を元に、遊び方、技術の役割、処理、引用コード、本人の記録を確認します。
profile.jsonのstatusは、制作・学習の内容確認前はdraft。本人と担当者が内容を確認したらpublishedにします。
サンプルはsampleのままにし、学生の制作・学習実績として集計しません。
未登録枠は学習成果の提出待ちです。空欄をAIに埋めさせないでください。

## プロジェクト全体のまとめ方

提出された各ケースの経験、AIの使用状況、完成した機能、本人の回答と変更実験を紹介します。
「今回の参加者では、こういう作品ができ、こういう説明を確認できた」という範囲で述べます。
8人・8作品の事例だけから、未経験者全員に同じ結果が出るとは結論づけません。
AIの更新による比較をしたい場合は、使用日・AI名・分かればモデル名・条件を記録します。分からない情報は未記録とします。
学生向けの詳細な記録と、公開用の3ページは分けて管理してください。
