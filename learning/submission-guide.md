# ゲーム説明・学習成果の提出と掲載

## 学生が用意するもの

自分のゲームのリポジトリに、たとえば `learning/` フォルダを作り、以下を保存します。

- 整理したコードとGitのコミット履歴
- `study-guide.md`：AI生成後にコードと照合した学習資料
- `workbook.md`：本人の回答・予測・変更結果・振り返り
- `prompt-log.md`：重要なプロンプト、日時、AI名、実行結果
- `profile.json`：ゲーム説明と3ページのWeb発表
- 必要なら、本人が撮ったゲーム画面（個人情報のないもの）

制作の履歴が残っていない場合は未記録とします。
ワークシートの個人的な記録すべてを公開する必要はありません。公開ページには説明・学習成果とその根拠を短く抜き出します。

## profile.jsonを作る

1. アーケードの `showcase/template.json` をコピーする。
2. プロンプト4へ、テンプレート、現行コード、本人の記録を渡す。
3. 本人が各項目を読み、存在する処理と実際の学習記録だけが書かれているかを確認する。
4. statusは、担当者が確認するまでdraftにする。

主な項目：

| 項目 | 内容 |
| --- | --- |
| schema_version | 1 |
| status | draft / sample / published |
| summary | ゲームのねらい・紹介 |
| audience | 学習資料の対象 |
| how_to_play | 操作・ルール・終了条件 |
| technologies | 技術名と、このゲームでの役割 |
| flow | 入力から結果までの順番 |
| source_root | コードのソースフォルダ。ランチャーからの相対パス |
| code_refs | 公開するコードのファイル・開始行・終了行・説明。1箇所30行以内、6箇所以内 |
| learning_goals | このコードで学ぶこと |
| questions | 理解確認の問題・ヒント・確認用の答え |
| creation | 制作のねらい、AIの助け、本人の担当、学習の証拠 |
| slides | ちょうど3ページ。見出し・要点・本文3項目以内・発表メモ |
| limitations | まだ分からないこと、対応範囲、未確認事項 |
| sources | 外部の資料や画像等の出典。http / httpsのURL |

任意でscreenshotに `/showcase/assets/ゲーム名.png` を指定できます。担当者が実際の画面をこのフォルダへ保存します（png / jpg / webp、5MB以下）。
スライド2の引用を選ぶ場合、slidesの2番目へcode_refを追加し、code_refsの番号を0から指定します。省略すると最初の引用を表示します。

code_refsの行番号は整理・変更後の実物を見て更新してください。非公開の設定・連絡先等は引用しません。
AIの出力に `code` キーがあっても不要です。掲載時に指定された行を実ファイルから読みます。
Webゲームのビルド済みフォルダがdistの場合、source_rootはdistではなく、元のソースがあるフォルダにできます。

## 担当者がアーケードへ登録する

例として、ゲームを `games/local/member-game` にクローン済みとします。

1. 作者のprofile.jsonを `showcase/member-game.json` にコピー。
2. source_rootを `games/local/member-game` など、実際のフォルダに合わせる。
3. games.jsonの該当枠に `"profile": "showcase/member-game.json"` を追加。
4. 次の検証コマンドで、形式とコード引用を確認する。

```powershell
.\.venv\Scripts\python.exe arcade.py --check
```

5. ランチャーを再起動し、カードの「紹介・技術」と「発表3ページ」を開く。
6. 本人と担当者が内容を確認し、statusをpublishedへ変更する。
7. 紹介資料とgames.jsonをアーケード側のGitで管理する。各ゲームのコードは各作者のリポジトリで管理する。

コードを再編集した場合は、引用行番号とスライドの内容も確認してください。
profile.jsonが未登録のゲームにも、記入前の紹介・発表のひな形を表示します。
型や行番号の検証に通ることと、学習成果の内容が正しいことは別です。本人の説明と記録を見て確認します。

## 3ページのWebスライド

1ページ目：私が作ったゲーム。何を作り、どう遊ぶか。
2ページ目：使った技術と仕組み。役割と、説明できる処理。
3ページ目：AIとの制作と学び。AIの助け、本人の判断・変更実験、残った課題。

画面の「前へ」「次へ」または左右キーで移動できます。Home / Endで最初・最後、全画面表示と発表メモも使えます。
「印刷 / PDF保存」では全3ページを出力できます。ブラウザーの印刷設定で背景のグラフィックを有効にすると、画面の配色に近くなります。
まだ学習成果がない段階では、AIに架空の成長や感想を作らせず、draftと空欄を残します。
